# Naming and Organisation

> Part of the **[Solution Structure](README.md)**.

## Purpose

Naming and organisation define how files, folders, projects and artefacts should be named and arranged.

Consistent naming helps repositories remain readable and predictable over time.

## Guidance

Names should communicate purpose and relationship.

A reader should not need deep project knowledge to understand what a folder or project is likely to contain.

### Use Consistent Patterns

Similar artefacts should follow similar naming patterns.

Consistency makes navigation easier and reduces avoidable decisions.

### Prefer Clear Names

Names should favour clarity over cleverness or excessive brevity.

Abbreviations should be used only when they are widely understood.

### Preserve Ordering Where Helpful

Numbered documentation folders can preserve lifecycle order.

Ordering should be used when it improves navigation, not as decoration.

### Avoid Ambiguous Buckets

Folders such as `Common`, `Shared`, `Misc` or `Utils` should be used carefully.

They often become places where unclear responsibilities accumulate.

### Rename When Understanding Improves

Names should evolve when the domain, architecture or responsibility becomes clearer.

Renaming is worthwhile when it reduces confusion and improves future understanding.

## Key Takeaways

- Names should communicate purpose and relationship.
- Similar artefacts should follow similar patterns.
- Clarity is more important than cleverness.
- Ambiguous buckets should be avoided.
- Renaming is useful when understanding improves.
