# Artefact Lifecycle

> Part of the **[Engineering Artefacts](README.md)**.

## Purpose

The artefact lifecycle defines how artefacts are drafted, reviewed, approved, revised and superseded.

## Guidance

Artefacts should evolve deliberately.

They should not become stale notes that nobody trusts.

### Draft

An artefact begins as a draft while the responsible role is still gathering context or shaping recommendations.

### Review

An artefact moves to review when it is ready for challenge by the intended consumers or approvers.

### Approval

An artefact is approved when it is accepted as a reliable input for the next lifecycle stage.

### Revision

An artefact may be revised when new understanding emerges.

Revisions should update version, date, owner and related artefacts where needed.

### Supersession

An artefact is superseded when a newer artefact replaces it.

Superseded artefacts may remain for traceability but should not be treated as current guidance.

## Key Takeaways

- Artefacts should have an explicit status.
- Approved artefacts become handover inputs.
- Revisions should be intentional.
- Superseded artefacts should remain traceable.
