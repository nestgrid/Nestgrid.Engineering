# Sample Maintenance

> Part of the **[Samples](README.md)**.

## Purpose

Sample maintenance keeps examples aligned with current standards, templates and engineering practices.

It ensures samples remain useful as the methodology evolves.

## Guidance

Samples should not be abandoned after creation.

Because samples teach by example, outdated samples can spread outdated practice.

### Review with Standards Changes

Samples should be reviewed when templates, documentation standards, architecture guidance or coding practices change.

The sample should continue to reflect the current methodology.

### Keep Dependencies Current

Implementation samples should maintain dependencies responsibly.

Outdated or insecure dependencies reduce trust in the sample.

### Remove Obsolete Samples

Samples that no longer teach useful practice should be revised or removed.

Keeping weak samples creates confusion.

### Preserve Learning Value

Maintenance should protect the sample's original learning goal.

Updates should not add complexity that makes the sample harder to understand.

### Link Back to Guidance

Samples should link to the guidance they demonstrate where practical.

This helps readers move from example to principle.

## Key Takeaways

- Samples require maintenance.
- Standards changes should trigger sample review.
- Implementation dependencies should stay current.
- Obsolete samples should be revised or removed.
- Maintenance should preserve learning value.
- Samples should link back to relevant guidance.
