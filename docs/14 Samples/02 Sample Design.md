# Sample Design

> Part of the **[Samples](README.md)**.

## Purpose

Sample design defines how samples should be structured so they are understandable and useful.

Good samples demonstrate the intended practice without unnecessary distraction.

## Guidance

A sample should be scoped deliberately.

It should include enough detail to teach the concept while avoiding unrelated complexity.

### Define the Learning Goal

Every sample should state what it demonstrates.

The learning goal should guide what is included and what is intentionally left out.

### Keep Scope Focused

Samples should not try to demonstrate everything at once.

Focused samples are easier to read, maintain and compare.

### Use Realistic Names and Structure

Samples should use realistic terminology and organisation.

Artificial examples can be useful, but they should still reflect believable engineering situations.

### Include Supporting Notes

Where helpful, samples should explain why key choices were made.

This helps readers understand the reasoning rather than only the final shape.

### Avoid Hidden Dependencies

Samples should be usable without undocumented setup or private knowledge.

Dependencies, assumptions and limitations should be visible.

## Key Takeaways

- Samples should have clear learning goals.
- Focused scope improves usefulness.
- Realistic structure makes samples easier to apply.
- Supporting notes should explain important choices.
- Hidden dependencies should be avoided.
