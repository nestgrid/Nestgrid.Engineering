# Operationalisation

This initiative captures the refinement that makes operationalisation a cross-cutting concern in the Nestgrid Engineering Operating System.

## Context

The lifecycle already includes Platform and Deployment guidance.

Applying the EOS to real products showed that deployability, installability, packageability, configurability, upgradeability, supportability and validation are product concerns that must be understood before Platform receives the work.

This is not specific to one product type. It applies to libraries, services, APIs, web applications, workers, command-line tools, mobile applications and other deliverable products.

## Objective

Update the EOS so operational requirements start in Discovery, are shaped by Architecture, implemented by Engineering, validated by Quality and Security, and realised by Platform.

## Scope

- Add Operational Requirements to Product Brief guidance.
- Add Operational Model guidance to Architecture artefacts.
- Add Operationalisation Plan guidance to Engineering artefacts.
- Update Quality, Security and Platform artefacts.
- Update lifecycle and role guidance.
- Add a Deployment chapter for Operationalisation.
- Record the architecture decision.
