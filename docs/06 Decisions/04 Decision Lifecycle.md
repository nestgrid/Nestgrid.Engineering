# Decision Lifecycle

> Part of the **[Decisions](README.md)**.

## Purpose

The decision lifecycle describes how decisions move from proposal to acceptance, revision or replacement.

It helps teams keep decision records current and trustworthy.

## Guidance

Decisions are not all permanent. Some remain stable for years, while others should change when context changes.

Decision records should show their current status so readers understand whether a decision still applies.

### Proposed

A proposed decision captures an option that is being considered.

It should contain enough context and rationale for review, but it should not be treated as final.

### Accepted

An accepted decision is the current agreed direction.

Implementation, documentation and related decisions should align with accepted records.

### Superseded

A superseded decision has been replaced by a later decision.

It should not be deleted because its history may still explain previous design or behaviour.

### Deprecated

A deprecated decision is still visible but should no longer guide new work.

This status is useful when migration or transition is required.

### Rejected

A rejected decision records an option that was considered but not chosen.

Rejected decisions can prevent repeated debate when the reasoning remains relevant.

## Key Takeaways

- Decisions have a lifecycle.
- Status helps readers understand whether a decision still applies.
- Accepted decisions guide current work.
- Superseded decisions preserve history.
- Rejected options can still be useful records.
