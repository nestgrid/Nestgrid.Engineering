# Ubiquitous Language

> Part of the **[Language](README.md)**.

## Purpose

Ubiquitous language is the shared vocabulary used by domain experts, stakeholders and engineers to describe the business domain consistently.

It helps ensure that the words used in conversations, documentation, models and code carry the same meaning across the team.

## Guidance

Software should reflect the language of the domain it serves. When people use the same word to mean different things, or different words to mean the same thing, misunderstanding enters the system.

Ubiquitous language reduces this risk by making important terms explicit and consistently used.

### Use Domain Language

Engineers should prefer the language used by the business domain over invented technical terminology.

Where technical language is necessary, it should not obscure the meaning of domain concepts.

### Make Meaning Explicit

Important terms should be defined clearly.

A term should not rely on assumed meaning if it affects requirements, rules, models, decisions or implementation.

### Use Language Consistently

The same concept should have the same name across conversations, documents, models, tests, APIs and code where practical.

Consistency reduces cognitive load and helps engineers recognise domain concepts throughout the solution.

### Refine Through Discovery

Language evolves as understanding improves.

Teams should expect terms to be challenged, clarified, renamed or split when deeper domain knowledge emerges.

### Resolve Ambiguity Early

Ambiguous terms should be discussed before they become embedded in models or code.

If a term means different things in different contexts, that difference should be captured rather than ignored.

## Key Takeaways

- Ubiquitous language creates shared understanding across disciplines.
- Domain language should be preferred over invented technical language.
- Important terms should be explicit and consistently used.
- Ambiguity should be resolved before it shapes design or implementation.
- Language should evolve as domain understanding improves.
