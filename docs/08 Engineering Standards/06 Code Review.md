# Code Review

> Part of the **[Engineering Standards](README.md)**.

## Purpose

Code review improves correctness, clarity, maintainability and shared understanding.

It is a quality practice and a collaboration practice, not merely an approval step.

## Guidance

Reviews should focus on meaningful issues: behaviour, design, readability, tests, security, reliability and alignment with standards.

The goal is to improve the work while respecting the people doing it.

### Review for Behaviour

Reviewers should check whether the code satisfies the intended behaviour.

Changes should be understood in relation to requirements, domain rules and expected outcomes.

### Review for Maintainability

Reviewers should consider whether future engineers can understand and safely change the code.

Complexity, naming, structure and dependencies should all be assessed.

### Review Tests

Tests should be reviewed with the same care as production code.

Reviewers should check whether the tests validate meaningful behaviour and protect important rules.

### Keep Feedback Constructive

Feedback should be specific, respectful and actionable.

Review should improve the codebase and the team's shared understanding.

### Use Approval Responsibly

Approval means the reviewer believes the change is acceptable for the codebase.

It should not be treated as a formality when important concerns remain unresolved.

## Key Takeaways

- Code review is a quality and collaboration practice.
- Reviews should focus on meaningful risks and improvements.
- Tests should be reviewed carefully.
- Feedback should be constructive and actionable.
- Approval should be given responsibly.
