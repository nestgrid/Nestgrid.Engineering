# Template Design

> Part of the **[Templates](README.md)**.

## Purpose

Template design defines how templates should be structured so they are useful, clear and maintainable.

Good templates help contributors produce better artefacts with less friction.

## Guidance

A template should be simple enough to use and specific enough to guide quality.

If a template is too heavy, people will avoid it. If it is too vague, it will not improve consistency.

### Include Required Sections

Templates should include the sections that are consistently needed for that artefact type.

Optional sections should be clearly indicated or omitted.

### Use Clear Prompts

Placeholder text should explain what the contributor should provide.

Prompts should be concise and practical.

### Keep Navigation Consistent

Documentation templates should include standard navigation where appropriate.

This supports discoverability across books and chapters.

### Avoid Over-Specification

Templates should not force every artefact to contain identical content.

They should provide structure while allowing the actual content to vary.

### Design for Maintenance

Templates should be easy to update when standards change.

Complex templates are harder to keep aligned with the methodology.

## Key Takeaways

- Templates should balance guidance and flexibility.
- Required sections should be clear.
- Prompts should be practical.
- Navigation should be consistent where relevant.
- Templates should avoid unnecessary rigidity.
- Maintainability matters.
