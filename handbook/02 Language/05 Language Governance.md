# Language Governance

> Part of the **[Language](README.md)**.

## Purpose

Language governance defines how shared terminology is maintained as understanding evolves.

It ensures that vocabulary remains accurate, consistent and useful throughout the engineering lifecycle.

## Guidance

Language should be stable enough to support shared understanding, but flexible enough to improve when better knowledge emerges.

Governance prevents terminology from becoming accidental, outdated or inconsistent across documents, models and code.

### Treat Language as a Living Asset

Shared language should evolve with the domain.

When new concepts are discovered or existing concepts are clarified, the glossary, documentation and related artefacts should be updated.

### Review Important Changes

Changes to significant terms should be intentional.

Renaming or redefining a key concept can affect requirements, models, tests, APIs, code and decisions. The impact should be considered before the change is adopted.

### Keep Definitions Consistent

Definitions should not drift across documents.

When a term is updated in one place, related references should be reviewed so the same concept remains consistently described.

### Preserve Useful History

Important terminology changes should explain why the change was made.

This helps future readers understand whether a term was renamed, replaced, split into multiple concepts or retired.

### Assign Ownership

The team should know who is responsible for maintaining language artefacts.

Ownership does not mean one person controls the language. It means someone ensures terminology remains visible, reviewed and current.

## Key Takeaways

- Shared language should be actively maintained.
- Terminology should evolve as understanding improves.
- Important language changes should be reviewed intentionally.
- Definitions should remain consistent across artefacts.
- Useful history should be preserved when terminology changes.
- Language ownership helps prevent drift and confusion.
