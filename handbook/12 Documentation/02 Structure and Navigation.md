# Structure and Navigation

> Part of the **[Documentation](README.md)**.

## Purpose

Structure and navigation define how documentation is organised and linked.

They help readers move through documentation without relying only on folder trees or prior knowledge.

## Guidance

Documentation should be easy to browse from entry points and easy to follow from any individual page.

Consistent structure reduces friction for readers and contributors.

### Use Predictable Structure

Similar documents should follow similar patterns.

Templates help readers know what to expect and help contributors write consistently.

### Link Related Documents

Documents should link to related material where it helps understanding.

Important relationships should be discoverable through hyperlinks, not only file location.

### Provide Local Navigation

Chapter documents should link to previous, next and parent documents where practical.

This makes reading possible from inside any page.

### Keep Entry Points Clear

Repository and book README files should act as strong entry points.

They should explain purpose, contents and where to go next.

### Avoid Broken Paths

Links should be reviewed when files are renamed, moved or deleted.

Broken links reduce trust in the documentation.

## Key Takeaways

- Structure should be predictable.
- Links make documentation discoverable.
- Local navigation improves reading flow.
- README files should act as entry points.
- Broken links should be avoided and fixed.
