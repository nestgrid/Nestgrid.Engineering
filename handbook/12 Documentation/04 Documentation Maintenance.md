# Documentation Maintenance

> Part of the **[Documentation](README.md)**.

## Purpose

Documentation maintenance keeps written knowledge accurate as systems, decisions and practices change.

It prevents documentation from becoming stale or misleading.

## Guidance

Documentation should be updated as part of normal engineering work.

If a change affects understanding, behaviour, decisions, operations or usage, related documentation should be considered.

### Update with Change

Documentation updates should happen close to the change that makes them necessary.

Delayed updates are often forgotten.

### Remove Obsolete Content

Outdated content should be revised or removed.

Keeping obsolete guidance creates confusion and reduces trust.

### Track Important Decisions

When documentation reflects a significant decision, it should link to the relevant decision record where practical.

This preserves reasoning and context.

### Review Navigation

Renames and moves should include link updates.

Navigation should remain reliable as the repository evolves.

### Keep Ownership Clear

Teams should know who maintains important documentation.

Shared ownership is useful, but complete lack of ownership leads to decay.

## Key Takeaways

- Documentation should be updated as part of engineering work.
- Obsolete content should be removed or revised.
- Decision records should be linked where useful.
- Navigation needs maintenance.
- Ownership helps prevent documentation decay.
