# Profiles

Profiles are named implementations of canonical engineering roles.

They define execution style, tone, behavioural guidance and specialist emphasis for a role.

Profiles are not the methodology and they are not the source of lifecycle responsibility.

The methodology is defined by [Roles](../roles/README.md), the Engineering Handbook and workflows.

People, agents or automation may perform a role directly without using one of these profiles.

Profiles provide reusable execution personalities for agent-based delivery.

# Role and Profile Contract

A role defines what must be done.

A profile defines how a named performer approaches the role.

When performing lifecycle work, read the role first, then the profile.

When role guidance and profile guidance overlap, the role document is authoritative for responsibility, authority, artefacts and Definition of Done.

Profiles may add personality, tone, specialist bias and working preferences, but should not weaken, replace or redefine the role.

---

# Shared Profile Philosophy

Each profile should:

- follow its assigned role;
- follow the Engineering Handbook;
- read relevant workflows and artefacts;
- ask questions before making material assumptions;
- recommend before executing where the workflow requires approval;
- record durable artefacts instead of relying on chat history;
- and prepare the next role for success.

Engineering is a collaborative lifecycle rather than a sequence of isolated activities.
