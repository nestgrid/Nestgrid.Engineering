# Changelog

All notable changes to the Nestgrid Engineering Operating System are recorded here.

The format follows the principles of [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), with release versions aligned to the repository's canonical [`VERSION`](VERSION) file and Git tags.

## [1.1.0] - Unreleased

This release contains the substantial refinement work completed after the `v1.0.0` milestone at [`b8aece6`](https://github.com/nestgrid/Nestgrid.Engineering/commit/b8aece69a35fdc492b629a97fd0443c3d6f85410). It is intentionally broad; future releases will be kept more focused.

### Added

- Opportunity Exploration as a dedicated, conversational workflow with explicit no-build and reuse outcomes.
- Operationalisation as a cross-cutting concern spanning Product, Architecture, Engineering, Quality, Security and Platform.
- Engineering artefact lifecycle guidance, metadata conventions and initiative-level artefacts.
- Independent Review as a canonical review series with stable findings, dispositions and review history.
- API Usage Guide guidance for documenting consumer workflows alongside OpenAPI.
- OpenAPI and Scalar development guidance.
- Bounded autonomy, Engineering Assurance and explicit approval-boundary guidance.
- Product-shape guidance distinguishing cohesive products from composed capability-oriented products.
- Logical versus physical architecture guidance, including qualified capability-module criteria and naming principles.
- Canonical EOS versioning through [`VERSION`](VERSION) and `eos_version` artefact metadata.
- Engineering Room orchestration for persistent, attributed multi-profile collaboration.
- Responsibility-based commit conventions, including the `[Governance]` prefix for EOS-owned changes.

### Changed

- Strengthened Product Owner discovery behaviour so conversation, evidence and shared understanding precede formal artefacts.
- Clarified the Product Brief and Architecture Handover as distinct Discovery outputs and approval responsibilities.
- Clarified Architecture's Recommend and Execute checkpoints.
- Clarified that Clean Architecture remains the logical discipline while physical solution organisation is an Architecture decision.
- Clarified Engineering responsibilities for implementing approved physical organisation without inventing boundaries.
- Clarified release approval ownership and the responsibilities of Quality, Security and Platform.
- Standardised development database migration guidance and API endpoint documentation expectations.
- Formalised role-based methodology and separated canonical Roles from execution Profiles.
- Expanded lifecycle, handover, template, sample and repository-structure guidance.
- Added workflow, prompt-sample and Sentinel guidance for independent review and multi-role collaboration.

## [1.0.0] - 2026-08-04

Initial tagged release of the Nestgrid Engineering Operating System, ending at [`b8aece6`](https://github.com/nestgrid/Nestgrid.Engineering/commit/b8aece69a35fdc492b629a97fd0443c3d6f85410).

### Added

- The initial Engineering Handbook covering philosophy, language, Discovery, Domain Modelling, Architecture, Decisions, Solution Structure, Engineering Standards, Testing, Deployment, Operations, Documentation, Templates, Samples, Engineering Workflow and Engineering Artefacts.
- Repository guidance, contribution guidance, security and conduct documentation.
- Markdown-first decision records, decision indexes and decision templates.
- Lifecycle mini-sample documentation demonstrating the methodology.
- Markdown link validation workflow and supporting repository validation.
- Standard engineering workflow and artefact books.
- Numbered lifecycle artefact directories and initiative-level artefact structure.
- Engineering Standards replacing the earlier Coding Standards organisation.
- Role-based methodology with canonical roles and named profiles.

### Changed

- Established the initial repository structure for the Engineering Operating System and its product-repository conventions.
- Expanded documentation, workflow, handover and artefact guidance through the initial release milestone.
