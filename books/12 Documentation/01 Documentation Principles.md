# Documentation Principles

> Part of the **[Documentation](README.md)**.

## Purpose

Documentation principles define what makes engineering documentation useful.

They guide how documentation is written, structured and maintained.

## Guidance

Documentation should exist to support understanding and action.

It should help readers make decisions, use systems, maintain software or understand reasoning.

### Write with Purpose

Every document should have a clear purpose.

If the purpose is unclear, the document is likely to become unfocused or unused.

### Know the Audience

Documentation should be written for the people who need it.

Engineers, stakeholders, operators and contributors may need different levels of detail.

### Preserve Reasoning

Documentation should explain important reasoning, not only final outcomes.

Understanding why something exists is often more valuable than knowing that it exists.

### Prefer Clarity

Clear documentation uses plain language, consistent terms and focused sections.

Complexity should be introduced only when the subject requires it.

### Keep It Alive

Documentation should evolve with the system.

Outdated documentation can be worse than missing documentation because it creates false confidence.

## Key Takeaways

- Documentation should support understanding and action.
- Every document needs a clear purpose.
- Audience matters.
- Reasoning should be preserved.
- Clarity is more important than volume.
- Documentation must be maintained.
