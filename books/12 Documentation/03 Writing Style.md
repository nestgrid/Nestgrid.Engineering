# Writing Style

> Part of the **[Documentation](README.md)**.

## Purpose

Writing style defines how documentation should sound and read.

It helps documentation remain clear, professional and easy to maintain.

## Guidance

Engineering documentation should be direct, accurate and readable.

It should explain enough to be useful without overwhelming readers with unnecessary detail.

### Be Clear

Use plain language where possible.

Avoid vague phrases when specific guidance is needed.

### Be Concise

Documentation should be detailed enough to help but brief enough to be read.

Long documents should be split into focused chapters or sections.

### Be Consistent

Use consistent terms, headings and navigation patterns.

Consistency helps readers move between documents without relearning structure.

### Be Precise

Important statements should be accurate and specific.

Avoid overpromising, exaggeration or guidance that cannot be applied.

### Use Examples Carefully

Examples should clarify the guidance.

They should not make the document product-specific unless the document is intentionally about a specific product.

## Key Takeaways

- Documentation should be clear and direct.
- Concision helps avoid TL;DR.
- Consistency improves readability.
- Precision matters.
- Examples should support the guidance without narrowing it unnecessarily.
