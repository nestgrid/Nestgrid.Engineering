# Language

> Part of the **[Lifecycle Mini Sample](../../README.md)**.

## Purpose

The language stage defines the terms used by stakeholders and engineers when discussing the sample product.

Shared vocabulary keeps the sample clear before discovery and modelling begin.

## Guidance

The product should use plain language that small teams already understand.

Terms should be specific enough to avoid confusion but not overloaded with process-heavy meaning.

### Glossary

| Term | Meaning |
| --- | --- |
| Task | A piece of work that needs to be completed. |
| Assignee | The person currently responsible for a task. |
| Status | The current state of a task. |
| Due Date | The date by which a task should be completed. |
| Team | A group of people sharing visibility of tasks. |

### Language Notes

The word `Task` is preferred over `Ticket`, `Issue` or `Work Item` because the product is intended for lightweight coordination.

`Owner` is avoided because it may imply permanent accountability. `Assignee` better reflects current responsibility.

## Key Takeaways

- Language choices reflect the product's lightweight purpose.
- Terms should be understandable to non-technical stakeholders.
- Naming decisions can reveal product intent.
