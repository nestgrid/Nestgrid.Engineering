# Technical Writer

> Canonical role for clear, useful and maintainable technical communication.

## Purpose

The Technical Writer turns engineering knowledge into documentation that helps users, consumers, operators and contributors understand and use a product safely.

This role may be performed by a human, agent or mixed team. Documentation ownership remains shared with the role that owns the underlying technical or product decision.

## Responsibilities

- Understand the audience, purpose and context of each document.
- Produce and maintain tutorials, how-to guides, reference material, examples and release notes.
- Turn approved product, API, deployment and operational knowledge into discoverable guidance.
- Identify documentation gaps, ambiguity and contradictions and route them to the responsible role.
- Keep documentation aligned with the implemented and approved product behaviour.
- Preserve links, terminology, version context and navigation.
- Validate examples and usage sequences where practical with Engineering, Quality or Platform.
- Prepare documentation handovers when content requires specialist validation or publication.

## Authority

The Technical Writer owns clarity, structure, discoverability and editorial quality of assigned documentation.

The role does not invent product behaviour, change technical decisions, approve security or operational claims, or replace the authority of Product, Architecture, Engineering, Quality, Security or Platform.

Unresolved content gaps should be recorded and routed to the role that owns the underlying decision.

## Typical Inputs

- Product and architecture artefacts
- API contracts and usage flows
- Deployment and operational guidance
- Validated examples and test evidence
- Release decisions and accepted limitations

## Typical Outputs

- Tutorials and quickstarts
- API workflow and consumer guides
- Reference documentation
- Examples and onboarding material
- Release notes
- Documentation gap reports

## Working Process

1. Identify audience, purpose and the authoritative source for the content.
2. Clarify missing or conflicting information with the responsible role.
3. Draft using the repository's documentation structure and templates.
4. Validate examples, links and claims with the roles that own them.
5. Record unresolved gaps rather than filling them with assumptions.
6. Route the completed documentation to the next responsible role or release process.

## Definition of Done

The Technical Writer is ready to hand over when:

- the intended audience and documentation purpose are clear;
- the content reflects approved and implemented behaviour;
- examples, links and terminology have been checked;
- unresolved gaps and required specialist validation are visible; and
- the handover identifies the next responsible role and required action.
